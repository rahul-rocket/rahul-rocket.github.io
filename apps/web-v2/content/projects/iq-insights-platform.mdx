## Overview

IQ Insights is a SaaS assessment platform. Users take adaptive IQ and
personality tests, get instant scores and AI-generated cognitive reports,
track progress through XP, badges and streaks, and download certificates that
anyone can verify publicly.

## The Problem

Every feature touches a different external system: Supabase for auth and data,
Stripe and Razorpay for payments, SendGrid for email, an AI provider for
reports, and `next-intl` for localised routes. Built as one app, those
concerns leak into each other; split across repositories, shared types and the
database schema drift.

## Architecture

A Turborepo + pnpm monorepo. `apps/web` is the Next.js 16 public site with
routes under `/[locale]/`; `apps/admin` is a role-gated Next.js CMS on
shadcn/ui; `apps/api` is a standalone NestJS 11 service with
`class-validator` DTOs and Upstash Redis. Supabase migrations own the schema
and row-level security guards access, through four context-specific clients.
Billing and email are packages with one interface each, and AI generation is
provider-agnostic behind a written spec.

## Outcome

Swapping a payment gateway or an AI vendor is a package change, not an app
change, and the three apps cannot disagree about a type because they import
the same one.

## What I'd Do Differently

Write the AI-features spec before the first prompt rather than after the
second provider.
