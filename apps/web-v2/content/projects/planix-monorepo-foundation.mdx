## Overview

Planix is the foundation for a fast, keyboard-first, dark-mode-first
project-management platform — self-hosted or SaaS, multi-tenant, aimed at the
space Linear, Plane and Jira occupy. The foundation is deliberately
feature-free: no auth, orgs, projects or tasks yet.

## The Problem

Product features are easy to add to a monorepo; structure is hard to add
later. Without enforced rules, UI packages start importing the database,
apps reach into each other, and every refactor becomes a migration.

## The Decision

Lock the architecture before the features, and write each locked decision as
an ADR. Dependencies point downward only — app → feature → data-access/ui →
sdk → util — and two tools enforce it: `turbo boundaries` tags and
`eslint-plugin-boundaries`.

## Architecture

`apps/web` is Next.js 15 on React 19; `apps/api` is NestJS 11 exposing health
and OpenAPI/Swagger; `apps/storybook` hosts the UI and design-system packages;
`apps/web-e2e` holds end-to-end tests. Domain contracts are Zod schemas in an
`sdk` package shared by web and API. Prisma on PostgreSQL, Redis, and per-app
Dockerfiles built with `turbo prune` complete the stack.

## Outcome

A foundation where a layering violation is a failing lint, not a code-review
comment — ready for the first business feature.
