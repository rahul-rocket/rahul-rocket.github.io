## Overview

KidzoRides is a booking platform for children's ride-on and electric toy car
rentals — birthday parties, school events and mall activations across India.
Customers browse a fleet, pick a date and duration, add extras and pay through
Razorpay; the operator then delivers, sets up and collects. WhatsApp is a
first-class booking channel alongside the web wizard.

## The Problem

Most of the repository's history — about 1,900 of 2,050 commits — came from
an AI app builder; my 144 commits are the hands-on work described here. The
product grew the way successful small products do: 136 Next.js route
handlers over the raw MongoDB driver and 31 collections, local-disk uploads,
and hand-rolled OTP auth. It worked, and it had three problems that would not
stay small — unsigned admin tokens, hardcoded admin credentials, and an
availability check that read, then wrote, leaving a window for two customers
to book the same car.

## The Decision

Fix what was dangerous now, and re-platform the rest deliberately rather than
in one rewrite. The repository became a Turborepo with `apps/web` and
`apps/admin` on pnpm, the security issues were closed first, and the target —
a NestJS API and worker, PostgreSQL on Supabase with Prisma, Supabase Auth and
Storage — is written down so the current state and the plan cannot be
confused.

## Challenges & Solutions

**Double booking.** Overlapping time ranges are not equality, so no unique
index can fully prevent them. The interim guard discretises each booking into
hourly slot keys and puts a unique index on those, which turns the race into a
loud duplicate-key error. The real fix is a Postgres `EXCLUDE USING gist`
constraint on the booking range — and that is the main reason for the
database migration.

**Admin security.** Admin sessions are now HS256 JWTs signed with `jose`, and
the first admin account is seeded from environment variables.

## Outcome

The product kept taking bookings throughout. The known issues are documented
in the repository rather than discovered in production, and the migration has
one concrete, testable reason to exist.

## What I'd Do Differently

Model bookings as ranges in a relational database from day one. The cost of
not doing so was invisible until there was enough traffic to race.
